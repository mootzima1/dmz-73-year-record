# Claude 작업 지시 — Jev(TypeSafe) 활용

이 문서는 DMZ 미니다큐 프로젝트에서 Claude가 Jev를 **글 생성기**가 아니라 **구조화된 검토 엔진**으로 사용하도록 지시한다.

## 시작 전

1. 프로젝트의 `CLAUDE_HANDOFF.md`와 `preproduction/` 폴더를 먼저 읽는다.
2. TypeSafe 스킬이 없다면 설치하고, 현재 TypeSafe 공식 문서를 확인한다.
3. API 키가 설정된 경우에만 Jev API를 호출한다. 키를 채팅·로그·소스코드·Git에 출력하거나 기록하지 않는다.
4. API 키가 없으면 Jev 호출을 흉내 내지 말고, 수동 검토로 진행하며 “Jev 미실행”이라고 기록한다.

## Jev의 역할

Jev는 아래 네 가지 판단만 맡는다.

1. **팩트 근거성** — 주장과 인용 출처가 실제로 연결되는가?
2. **현재성/보류 여부** — 2026년 사건처럼 최신 발표를 다시 확인해야 하는가?
3. **저작권 메타데이터 완결성** — 자산에 원본 URL·라이선스·출처 문구·사용 타임코드가 모두 있는가?
4. **표현 안전성** — 대본이 미확정 원인을 단정하거나 특정 정부·정당을 평가하는가?

Jev의 결과는 자동 승인이나 진실 보증이 아니다. 확률·신뢰도와 함께 **사람 검토 우선순위**를 정하는 용도로만 쓴다.

## 반드시 사용할 입력 파일

- `preproduction/03_sources.md`
- `preproduction/04_factcheck.md`
- `preproduction/05_script_v1.md`
- `source/SOURCES.md`

## Jev 질문 설계

같은 자료 묶음에 독립적인 질문은 한 번의 요청으로 함께 보낸다. 질문은 짧고 한 가지 판단만 담는다.

### A. 팩트체크 — Choice

각 `04_factcheck.md` 행마다 다음 선택지 중 하나를 고른다.

- `supported`: 제공된 1차 출처가 주장 전체를 직접 뒷받침한다.
- `partially_supported`: 일부만 뒷받침하거나 표현을 약하게 해야 한다.
- `unsupported`: 제공된 출처로는 주장할 수 없다.
- `needs_fresh_check`: 최신 발표 또는 추가 1차 출처가 필요하다.

질문 상태에는 `claim`, `source_excerpt`, `source_url`, `source_date`를 넣는다. 출처 원문이 없으면 `unsupported`로 처리하고 검색 결과 요약만으로 승인하지 않는다.

### B. 2026 사건 최신성 — Noul

매번 다음을 확인한다.

> `latest_official_release`가 2026년 9월 28일 이후의 최종 조사 결과 또는 그에 준하는 업데이트를 포함하는가?

결과가 낮거나 최신 발표를 확보하지 못하면 화면·대본에는 반드시 다음처럼 귀속한다.

`국방부 중간 판단(2026.9.28)`

`북한이 설치했다`, `확정됐다` 같은 단정문은 쓰지 않는다.

### C. 자산 권리 완결성 — Noul

`source/SOURCES.md`의 자산 한 행마다 다음을 판단한다.

> 파일명, 출처기관, 원본 URL, 정확한 라이선스 또는 허가 근거, 다운로드 날짜, 크레디트 문구, 씬/타임코드가 모두 있고 편집·유튜브 게시에 부합하는가?

`false` 또는 불확실하면 상태를 `권리 확인 필요`로 유지한다. 해당 파일은 프록시·최종 타임라인·렌더링에 넣지 않는다.

### D. 대본 안전성 — Noul

`05_script_v1.md`의 문단별로 독립 실행한다.

1. 이 문단이 2026 사고의 지뢰 종류·매설 주체·매설 시기를 확정적으로 단정하는가?
2. 이 문단이 2015 사건에서 국방백서의 귀속, 북측 당시 주장, 8·25 공동보도문의 유감 표명을 하나의 사실처럼 합치는가?
3. 이 문단이 특정 정부·정당의 성과·실패를 평가하는가?
4. 이 문단이 실제 역사 자료처럼 보이는 AI 재현 또는 미확인 영상을 요구하는가?

하나라도 높은 확률로 `true`면 해당 문단은 자동 사용 금지로 표시하고, 사람이 수정할 수 있도록 문제 문장과 이유만 보고한다.

## 결과 기록 형식

Jev 호출 결과를 새로 만들 `preproduction/10_jev_review.md`에 아래 형식으로 기록한다. API 키·요청 전문·불필요한 원문은 저장하지 않는다.

```md
## 실행 기록

- 실행일: YYYY-MM-DD
- 모델: jev-latest
- 입력 파일: ...
- 최신 공식 발표 확인일: ...

| 대상 | 판단 | 확률/신뢰도 | 조치 |
|---|---|---:|---|
| 2026 사건 문장 | needs_fresh_check | 0.82 / 0.71 | 국방부·합참·유엔사 재확인 |
| asset_001.mp4 | false | 0.95 | 권리 확인 전 사용 금지 |
```

## 의사결정 규칙

- `unsupported`, `needs_fresh_check`, 권리 완결성 `false` → 자동 제외 또는 사람 검토 대기.
- Choice/Score 신뢰도 0.75 미만 → 사람 검토 대기. 단, 원인 단정·저작권·안전 관련 항목은 신뢰도와 무관하게 보수적으로 보류한다.
- `supported`라고 나와도 출처의 라이선스는 별도로 검토한다.
- Jev가 판단하지 못하는 역사적 맥락, 법률 해석, 저작권 최종 허가 여부는 사람이 결정한다.

## 절대 금지

- Jev의 결과만으로 역사적 사실·사고 원인·저작권 사용 허가를 확정하지 않는다.
- API 키를 클라이언트 앱, 문서, 영상 자막, Git, 스크린샷에 넣지 않는다.
- 실제 폭발 영상이 없을 때 가짜 폭발 영상 또는 AI 재현을 실제 사건처럼 사용하지 않는다.
- 사용자의 명시적 검토·승인 전에는 다운로드 대량 실행, 최종 렌더링, 공개 업로드를 하지 않는다.
